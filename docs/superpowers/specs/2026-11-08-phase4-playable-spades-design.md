# Phase 4 — Playable offline Spades: design

Status: APPROVED by the owner on 2026-11-08 (including the Figma screen designs). Nothing is built yet.

Screen designs (10 screens, tablet landscape): https://www.figma.com/design/7RQIrZcBikcB5AexEh1pUP

## Goal
Connect the Phase 2 table screen to the Phase 3 Spades rules engine so the owner can play a complete game of Spades on the PC: **1 human (South) + 3 bots**, from a start screen to a winner screen. No multiplayer yet, but the design must not get in the way of Phase 5 (Wi-Fi) and Phase 6 (Bluetooth).

## Non-goals
- No networking, no Join Game (the button is shown greyed out, "Coming soon").
- No real card artwork, avatars or recorded sounds (dummy cards stay; sounds are generated placeholders).
- No saving a game in progress (closing the app loses it).
- No time limit for playing a card (the owner asked; not decided yet. Possible later host option: none / 15 / 30 / 60 seconds, a bot plays when time runs out. Logged in `docs/OPEN_QUESTIONS.md`).
- No 29, no tablet run (separate items).
- Anti-goal: the screen must never hold or learn other players' cards. It only receives what `SpadesGame.view_for(0)` gives (own hand, counts, public info).

## What the owner decided (this conversation)
1. **Start screen** with four buttons: Join Game (greyed, coming soon), Host Game, Settings, Exit. Host Game opens the **host options**: Blind Nil, normal Nil, redeal, bags penalty, play-higher, win score, lose score (defaults as in `docs/SPADES_RULES.md`). A game ends on a **winner screen** with Play again and Exit to start.
2. **Bidding:** a row of number buttons; Nil and Blind Nil have their own buttons; Blind Nil is chosen *before* you look at your cards (hand stays face-down until your bid when Blind Nil is on). Other players' bids show beside their names.
3. **Blind Nil swap:** you see your own cards; your partner's cards are face-down for you to tap; the number you give equals the number you take (1 or 2).
4. **Playing:** cards you may not play are greyed out; played cards show in the middle; the last trick can be looked at; bots play after a short pause.
5. **Always visible:** both team scores, bags, each player's bid and tricks won, whether spades are broken, whose turn it is. After each round a **round summary** box (points, bags, Nil results) with a Next round button.
6. Dummy cards stay; sound = placeholders. Losing the game when the app closes is fine. No quick-restart button.

## My calls (the owner can overrule)
- Number buttons run **1 to 13**; Nil is its own button (the rules treat them differently).
- Face-down hand during bidding applies only when Blind Nil is enabled by the host; otherwise your cards show from the start.
- The existing **Info** button opens a small panel with the last trick and all bids; **Menu** opens Resume / Exit to start.
- The Settings screen only has a **sound on/off** switch for now.
- Placeholder sounds are tiny beeps **generated by code** (no files, nothing to license).
- Bot pause: about 0.7 s per bot card; a finished trick stays visible for about 1.2 s, then is swept to the winner.

## Architecture
Layers stay separate (see `docs/ARCHITECTURE.md`):

```
UI scenes  --(actions: bid / swap / play)-->  SpadesSession  --> SpadesGame (rules, host-authoritative)
UI scenes  <--(TableState built from view_for(0))--  SpadesSession  <-- SpadesBot x3
```

- **`SpadesSession`** (new, `core/spades/`, no UI): owns one `SpadesGame` and three `SpadesBot`s. It is the *host*: it accepts the human's actions, rejects illegal ones, and `advance_bots()` makes exactly one bot action when it is a bot's turn (the UI calls it after each pause, so the class needs no timers and stays testable). It reports events (`bid_made`, `card_played`, `trick_finished`, `round_finished`, `game_finished`). In Phase 5 the same class becomes the host that talks to remote players, which is why the UI only ever talks to it through these few actions and events.
- **`TableStateBuilder`** (new): turns `game.view_for(0)` into the `TableState` the table already draws. `TableState` gains bids, spades-broken, legal-card set and last trick.
- **UI** (new scenes in `ui/`): `Main` (swaps screens), `StartScreen`, `HostOptionsScreen`, `SettingsScreen`, `BidPanel`, `SwapPanel`, `RoundSummary`, `InfoPanel`, `WinnerScreen`, and a small `SoundBank` for placeholder sounds. `Table` and `HandView` are extended (greyed illegal cards, other seats' played cards animate in, trick sweep), not rewritten.
- Rules logic is not touched except where tests prove a gap.

## Testing and "done"
- Automated: session tests (human actions accepted/rejected, bots advance, whole games end, no private card ever in a `view_for(0)`-built `TableState`), builder tests, UI smoke tests in the Phase 2 style.
- By eye: screenshots of every screen at several window sizes, plus the owner playing one full game on the PC.
- **Done when** a full game can be played offline from start screen to winner screen, all tests pass, and the owner has played it.

## Risks
- The tablet has not run anything yet; touch behaviour of the new buttons is unverified until Phase 1.
- Bots never bid Blind Nil, so the swap screen only gets exercised by the human. We will test it with a scripted human.
- Look and feel is basic; polish is Phase 9.
